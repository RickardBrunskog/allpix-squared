## Description

The `InteractivePropagation` module transports electrons and holes through the sensitive sensor volume while including the electric field generated by the other propagated charge groups. It is based on `TransientPropagation`, but propagates all applicable charge groups synchronously so that their direct Coulomb interactions can be evaluated during transport.

The carrier drift is integrated with a classical fourth-order Runge--Kutta (RK4) method. The velocity is calculated from the sum of the detector electric field and the Coulomb field, together with the selected mobility model and, when present, the magnetic field. Diffusion, recombination, trapping, detrapping, surface reflection, and Shockley--Ramo signal induction are handled during propagation. A weighting potential is therefore required.

Direct Coulomb evaluation scales approximately quadratically with the number of propagated charge groups. The values of `charge_per_step`, `max_charge_groups`, and `coulomb_distance_limit` can consequently have a large effect on both runtime and accuracy.

For ordinary propagation, the positions and states of all Coulomb sources are frozen at the beginning of each outer time step. Every RK4 stage evaluates source activation at the stage time using the local deposition time. This avoids target-order-dependent source fields while retaining the existing independently stepped propagation outside the optional coupled first-step refinement.

### Coulomb-field treatment

The direct field uses the configured relative permittivity and includes only source groups whose separation from the target is smaller than `coulomb_distance_limit`. Groups that have not yet been deposited, have recombined, or have reached a sensor surface are not used as Coulomb sources. Trapped groups remain sources.

An optional Plummer softening length can regularize close interactions. For a source charge $`q`$, separation vector $`\mathbf{r}`$, and softening length $`\epsilon`$, the softened field is proportional to

$`\frac{q\mathbf{r}}{\left(r^2+\epsilon^2\right)^{3/2}}`$.

With zero softening, distinct charge groups at exactly the same position are assigned a small deterministic, pair-antisymmetric separation. This avoids non-finite fields without consuming random numbers. With non-zero softening, an exactly overlapping pair contributes zero field.

The Coulomb-field limit can be applied either to every direct and mirror-charge contribution separately or once to the magnitude of the final summed Coulomb vector. In summed mode, the direction of the combined field is preserved.

### Mirror charges

Mirror-charge contributions can be enabled for sensors that are approximately described by two parallel constant-potential planes normal to the local z-axis. The planes are placed at the lower and upper z boundaries of the detector model. This approximation also includes the mirror contributions of a charge group to itself. It should only be used when this simplified electrode geometry is appropriate.

## Parameters

### Transport and grouping parameters

| Parameter | Default | Description |
|---|---:|---|
| `temperature` | `293.15K` | Sensor temperature used by the mobility, diffusion, trapping, and detrapping models. Must be finite and greater than zero. |
| `mobility_model` | `jacoboni` | Charge-carrier mobility model. Available models are described in the user manual. |
| `recombination_model` | `none` | Charge-carrier lifetime model. Models other than `none` require a detector doping profile. |
| `trapping_model` | `none` | Radiation-damage trapping model. Models other than `none` require `fluence`. |
| `detrapping_model` | `none` | Radiation-damage detrapping model. |
| `fluence` | no default | 1 MeV-neutron-equivalent fluence required by the trapping models. |
| `charge_per_step` | `1` | Nominal number of carriers represented by one propagated group. The module can increase the effective value to satisfy `max_charge_groups`; the final remainder group from each deposit can be smaller. Must be greater than zero. |
| `max_charge_groups` | `1000` | Approximate event-wide limit on the number of propagated groups. The module raises the effective `charge_per_step` when necessary. Per-deposit remainder groups can cause the limit to be exceeded slightly. A value of `0` disables this limit. |
| `timestep` | `0.01ns` | Outer RK4 time step and induced-pulse bin width. Must be finite and greater than zero. |
| `integration_time` | `25ns` | Maximum local time for propagation. Deposits later than this are ignored. Must be finite and greater than zero. |
| `distance` | `1` | Maximum pixel-index distance used for Shockley--Ramo induction. `0` selects only the pixel below the carrier, `1` normally selects a 3x3 region, and `2` a 5x5 region. |
| `ignore_magnetic_field` | `false` | Ignore the detector magnetic field even when one is configured. |
| `enable_diffusion` | `true` | Apply thermal diffusion. Disabling diffusion is intended for diagnostic studies and generally does not yield a complete physical transport model. |
| `propagate_electrons` | `true` | Propagate electron-type deposits. |
| `propagate_holes` | `true` | Propagate hole-type deposits. |
| `surface_reflectivity` | `0.0` | Probability that a carrier is reflected rather than absorbed at a sensor surface. Must lie in the interval `[0, 1]`; `0` means no reflection and `1` total reflection. |

The parameters `multiplication_model`, `multiplication_threshold`, and `max_multiplication_level` are accepted for compatibility with the propagation infrastructure, but impact-ionization carrier creation is not implemented in this module. They should not be used to enable charge multiplication in `InteractivePropagation`.

### Coulomb parameters

| Parameter | Default | Description |
|---|---:|---|
| `enable_coulomb_repulsion` | `true` | Include the Coulomb field generated by the other eligible charge groups. If this is disabled, `TransientPropagation` is normally the more appropriate module. |
| `relative_permittivity` | `1.0` | Relative permittivity used for direct and mirror-charge fields. It must be finite and greater than zero when Coulomb interactions are enabled. The default corresponds to vacuum and should be replaced by the value for the sensor material, for example approximately `11.7` for silicon. |
| `coulomb_distance_limit` | `200um` | Maximum source--target distance for direct and mirror-charge contributions. Contributions at or beyond the limit are omitted. Must be finite and non-negative. |
| `coulomb_field_limit` | `4e5V/cm` | Non-negative upper limit applied according to `coulomb_field_limit_mode`. A value of zero suppresses the returned Coulomb field. |
| `coulomb_field_limit_mode` | `pair` | Field-limiting strategy. `pair` caps each direct and mirror contribution before summation; `summed` caps the magnitude of the final direct-plus-mirror vector while preserving its direction. The only allowed values are `pair` and `summed`. |
| `coulomb_softening_length` | `0nm` | Plummer softening length used by all production Coulomb evaluations, including optional first-step refinement. Must be finite and non-negative. Zero selects point-charge behavior with deterministic exact-overlap regularization. |
| `include_mirror_charges` | `false` | Include image charges from the two local-z sensor boundaries under the parallel-plate approximation described above. |

### First-step refinement and diagnostics

| Parameter | Default | Description |
|---|---:|---|
| `enable_coulomb_initial_step_refinement` | `false` | Replace the first production outer step with a simultaneously coupled RK4 calculation on a refined time grid. This changes the propagated trajectory. |
| `coulomb_initial_step_refinement_factor` | `4096` | Requested maximum refined substep expressed as `timestep / factor`. Charge-activation times inside the first outer step are retained as interval boundaries. Must be greater than zero when production refinement is enabled. |
| `enable_coulomb_refinement_diagnostics` | `false` | Run a diagnostic coupled-RK4 shadow calculation for the first outer step. The shadow calculation reports endpoint convergence but does not alter the production trajectory. It is extremely computationally expensive. |
| `coulomb_refinement_softening_length` | `coulomb_softening_length` | Softening length used only by the diagnostic shadow calculations. This permits comparison against a different regularization without changing production propagation. Must be finite and non-negative. |
| `coulomb_refinement_charge_weighted_rms_tolerance` | `1nm` | Acceptance tolerance for the charge-weighted RMS endpoint difference between adjacent shadow refinements. Must be finite and non-negative. |
| `coulomb_refinement_max_endpoint_tolerance` | `10nm` | Acceptance tolerance for the largest individual endpoint difference between adjacent shadow refinements. Must be finite and non-negative. |
| `enable_coulomb_production_statistics` | `false` | Accumulate and report statistics from Coulomb evaluations used by the actual trajectory. This does not enable the refinement sweep. |

Production first-step refinement has the following behavior:

* It requires `enable_coulomb_repulsion = true`.
* It cannot be enabled together with `enable_coulomb_refinement_diagnostics`.
* It retains deposition-time activation boundaries within the first outer step and advances all active groups together on each refined subinterval.
* When diffusion is enabled, one operator-split diffusion kick is applied after each refined drift substep using the common pre-drift source state.
* Later outer steps continue with the ordinary independently stepped RK4 propagation and frozen beginning-of-step source states.

The diagnostic shadow sweep currently evaluates refinement factors 1024, 2048, and 4096. The 1024 result is compared with the sequential production shadow and is not used for acceptance. The 2048-versus-1024 and 4096-versus-2048 comparisons are assessed using both configured tolerances. Diagnostic logs also report activation intervals, pair and field statistics, endpoint-error distributions, and the largest individual endpoint errors.

When `enable_coulomb_production_statistics` is enabled, the module reports production softening and field-limit settings, field-evaluation and eligible-pair counts, exact-overlap and softening statistics, field-cap counts, minimum pair separation, maximum field magnitudes, and final carrier-state counts separately for electrons and holes.

## Propagation-summary output

| Parameter | Default | Description |
|---|---:|---|
| `output_propagation_summary` | `false` | Dispatch a `PropagationSummaryMessage` containing time-resolved charge-cloud statistics. |
| `output_propagation_summary_step` | `timestep` | Requested interval between summary samples. It must be finite and greater than zero when summary output is enabled. Samples are emitted on the module's outer time grid. |

At each sampled time, the summary includes charge groups that have already been deposited and are not in the `RECOMBINED` or `TRAPPED` state. Groups in the `HALTED` state are retained. Electron and hole statistics are calculated separately and weighted by the number of carriers in each group.

Each ROOT-serializable `PropagationSummary` object provides:

| Quantity | Electron getters | Hole getters |
|---|---|---|
| Carrier data present | `hasElectrons()` | `hasHoles()` |
| Charge-weighted mean local position | `getMeanXE()`, `getMeanYE()`, `getMeanZE()` | `getMeanXH()`, `getMeanYH()`, `getMeanZH()` |
| Charge-weighted RMS spread in x, y, and z | `getRMSXE()`, `getRMSYE()`, `getRMSZE()` | `getRMSXH()`, `getRMSYH()`, `getRMSZH()` |
| Total three-dimensional RMS spread | `getRMSEE()` | `getRMSEH()` |
| Minimum and maximum local x | `getMinXE()`, `getMaxXE()` | `getMinXH()`, `getMaxXH()` |
| Minimum and maximum local y | `getMinYE()`, `getMaxYE()` | `getMinYH()`, `getMaxYH()` |
| Minimum and maximum local z | `getMinZE()`, `getMaxZE()` | `getMinZH()`, `getMaxZH()` |

The sample time is available through `getLocalTime()`. If no eligible group of a given carrier type is present, its availability flag is false and all of its numerical fields are stored as `NaN`. The objects can be persisted with the standard Allpix Squared ROOT object writers.

Per-event line graphs, animations, and RMS plots disable parallel event processing for this module. Summary-object output and the non-graphical production statistics do not by themselves disable multithreading.

## Usage

A production configuration with Coulomb transport and time-resolved summary output can be written as:

```ini
[InteractivePropagation]
temperature = 293.15K
timestep = 0.05ns
integration_time = 100ns

charge_per_step = 30
max_charge_groups = 1500
distance = 0

enable_diffusion = true
enable_coulomb_repulsion = true
relative_permittivity = 11.7
coulomb_distance_limit = 200um
coulomb_field_limit = 4e5V/cm
coulomb_field_limit_mode = "pair"
coulomb_softening_length = 0nm
include_mirror_charges = false

propagate_electrons = true
propagate_holes = true

output_propagation_summary = true
output_propagation_summary_step = 0.1ns
```

To replace the first production step with the coupled refined calculation, add:

```ini
enable_coulomb_initial_step_refinement = true
coulomb_initial_step_refinement_factor = 4096
```

For a diagnostic-only convergence run, keep production refinement disabled and use for example:

```ini
enable_coulomb_initial_step_refinement = false
enable_coulomb_refinement_diagnostics = true
coulomb_refinement_softening_length = 5nm
coulomb_refinement_charge_weighted_rms_tolerance = 1nm
coulomb_refinement_max_endpoint_tolerance = 10nm
enable_coulomb_production_statistics = true
```

The diagnostic sweep is intended for a small number of events and charge groups because its runtime can be many times that of ordinary production propagation.
